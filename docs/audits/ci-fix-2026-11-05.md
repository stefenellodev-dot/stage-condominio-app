# Corrección de CI (startup failure) — 2026-11-05

Tarea 6 del plan [2026-11-05-post-audit-hardening](../superpowers/plans/2026-11-05-post-audit-hardening.md): CI mínimo.

## Problema

Todos los runs de GitHub Actions fallaban en **0 segundos y sin check-runs** (p. ej. run `42133450458`):

- Mensaje: *"This run likely failed because of a workflow file issue"*.
- Check-suite `114169959121` con conclusion `failure` y **0 check-runs** — startup failure: el workflow ni siquiera arrancaba jobs.
- El YAML era sintácticamente válido (`yaml.safe_load` OK), por lo que no aparecía como error de parseo.
- Ocurría desde al menos 2026-11-04, en todos los pushes a `main`.

## Diagnóstico

El job `rls` tenía:

```yaml
rls:
  runs-on: ubuntu-latest
  if: secrets.DATABASE_URL != ''
```

Según [la referencia de contextos de GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts),
`jobs.<job_id>.if` solo admite los contextos `github`, `needs`, `vars` e `inputs`.
El uso de `secrets` en ese nivel produce un startup failure silencioso de todo el
workflow (nadie aparece en la UI salvo el check-suite fallido).

## Corrección

Commit `b2d7b21` — la condición se evalúa a nivel de paso vía `env` (que sí admite `secrets`):

```yaml
rls:
  runs-on: ubuntu-latest
  env:
    HAS_DATABASE_URL: ${{ secrets.DATABASE_URL != '' }}
  steps:
    - uses: actions/checkout@v4
    - run: sudo apt-get update && sudo apt-get install -y postgresql-client
    - name: Run RLS suite
      if: env.HAS_DATABASE_URL == 'true'
      env:
        DATABASE_URL: ${{ secrets.DATABASE_URL }}
      run: psql -v ON_ERROR_STOP=1 "$DATABASE_URL" -f tests/rls/rls-tests.sql
```

## Verificación

- Run [42133892275](https://github.com/stefenellodev-dot/stage-condominio-app/actions/runs/42133892275): `jobs=[build:success, rls:success]`.
- Pasos del job `rls`: `Run RLS suite` quedó **skipped** (correcto: el secreto `DATABASE_URL` no está configurado aún en GitHub; la condición lo salta en vez de fallar).
- Check-runs sobre HEAD (`b2d7b21`): `build=success`, `rls=success`.
- Branch protection de `main` exige solo el check `build` (strict=false, no enforce admins). El `rls` no se exige porque sin el secreto siempre pasaría vacío; se exigirá cuando `DATABASE_URL` exista como secreto.

## Pendiente

- Crear el secreto `DATABASE_URL` en GitHub (Settings → Secrets and variables → Actions) apuntando a la base stage, y entonces añadir `rls` a los required_status_checks con confirmación de que el paso ejecuta psql (34/34).
- Nota: al ejecutarse contra la base real, la suite corre cada caso en su transacción con `ROLLBACK` (sin mutar datos).
